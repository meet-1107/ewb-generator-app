# Screen 01 — Login and account access

## Purpose

Make authentication the first screen, then get a new vendor into the business setup flow without exposing any invoice, GST, or EWB information before sign-in.

## Layout

1. App mark and short promise: “Create and manage e-way bills from your invoices.”
2. Email or mobile number field.
3. Password field with show/hide and reset link.
4. Primary **Sign in** button.
5. **Create account** link and terms/privacy links.
6. Loading, validation, network, and Firebase authentication error states.

Offer phone OTP only if enabled and supported by the chosen Firebase Auth configuration. Do not imply a method is available until configured.

## Behavior

- Validate required fields locally; authenticate with Firebase Auth.
- Keep the session using the platform's secure auth persistence.
- After sign-in, route existing users to Dashboard; route users without a business profile to Business setup.
- Password reset sends the Firebase reset flow and shows a neutral confirmation.
- Account creation collects name, email/mobile, and password, verifies the contact, then creates the user's private workspace/business profile.
- Sign-out is available only under Account settings and clears local sensitive caches.

## Data and implementation

- Firebase Auth owns credentials; never store passwords in Firestore.
- Use a stable Firebase `uid` as the user identity and scope all app queries by membership.
- Create an initial `users/{uid}` profile and a business/workspace only after a verified account flow.
- Do not log passwords, OTPs, access tokens, or full invoice/GST data to analytics or console logs.

## Acceptance checks

- Unauthenticated launch always lands here.
- Wrong credentials, no connection, and rate limiting each have understandable recovery text.
- A newly registered user cannot reach Dashboard until required business setup is complete.
