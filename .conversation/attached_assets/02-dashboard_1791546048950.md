# Screen 02 — Dashboard

## Purpose

Show a vendor the few numbers and actions that help them decide what to do next, without making them navigate through reports.

## Layout

- Header: business name, active GSTIN selector (when multiple GSTINs exist), notification/help entry.
- Greeting and last-sync timestamp.
- Four compact summary cards: **Invoices this period**, **EWB generated**, **Active EWB**, **Expired EWB**. Each card opens the relevant filtered list.
- A GST status strip for **GSTR-1**, **GSTR-2**, and **GSTR-3B**, with period, status, and last checked time. Tap opens GST status.
- Primary actions: **Create invoice** and **Import invoice PDF**.
- Recent activity list: recent invoices and EWB state changes; tap opens the record.
- Empty state explains the first step and provides one primary action.

## Behavior

- Load business-scoped counts and recent records from Firestore; use server-computed/provider status where relevant.
- Show `—` / “Not checked” for unavailable status. Never present a missing value as zero or compliant.
- Pull to refresh; show stale/offline data with its last-updated time.
- For multiple GST registrations, all summary numbers and GST states must match the selected GSTIN.

## Data

- Read a lightweight dashboard aggregate, or query indexed business collections with bounded date ranges.
- GST status comes from a provider sync record, not a guessed calculation from invoices.
- Counts should be derived in trusted backend code or bounded queries, not trusted from a client-written aggregate.

## Acceptance checks

- A first-time vendor can create/import an invoice directly from the screen.
- Tapping each count opens a correctly filtered list.
- No unverified GST return status is labeled filed, verified, or compliant.
