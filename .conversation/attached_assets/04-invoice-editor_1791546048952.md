# Screen 04 — Create/edit invoice

## Purpose

Capture invoice details once, in a guided form that can be reused to prepare an EWB. The user's requested fields remain editable.

## Form sections

### Seller and buyer

- Seller business name, address, GSTIN, state, and dispatch-from address.
- Buyer/receiver name, address, GSTIN (optional only where legally allowed), state, and ship-to address.
- Offer saved parties for reuse; allow editing before saving.

### Invoice

- Invoice number, invoice date, document type, place of supply, and supply type.
- Six reusable invoice layouts/templates; selecting one changes presentation/default sections, not the legal values silently.

### Products and charges

- Repeatable line items: product name/description, HSN/SAC, quantity, unit, taxable amount, GST rate, CGST/SGST/IGST, and line total.
- Additional charges/discounts if supported by the invoice schema.
- Automatic totals, with a visible edit/review path and clear rounding rules.

### Transport and EWB details

- Transporter name and transporter ID/GSTIN where applicable.
- Vehicle number, mode of transport, distance in km, and dispatch/delivery details.
- Do not guess legally required EWB values. Validate against current provider/API rules before submission.

## Actions and interaction

- Save draft autosaves after a short pause and also offers an explicit **Save draft** action.
- **Continue to EWB** validates the invoice and opens the EWB review screen; no EWB request is made from this screen.
- Keep a clear progress indicator: Invoice → Review EWB → Generated.
- Mark required fields and show inline errors; preserve entered data if navigation or validation fails.
- Show a sticky total summary on small screens, with line items editable in a dedicated subview if needed.

## Validation

- GSTIN/state/pincode formats and invoice date/document fields receive basic client-side validation.
- Product amounts and tax totals are recalculated in trusted code or a shared deterministic domain module; show discrepancies rather than silently changing user input.
- Final EWB-specific validation is performed again by the backend/provider immediately before submission.

## Data

- Save a typed invoice document with `status: draft | ready | ewb_generated`.
- Record `createdBy`, `updatedBy`, timestamps, schema version, selected template/version, seller GSTIN, totals, and line items.
- Preserve original parsed/imported values when PDF import was used; track user corrections separately if auditability is required.
