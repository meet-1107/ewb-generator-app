# Screen 07 — EWB detail

## Purpose

Let the user inspect a generated bill and access a clean, printable/downloadable copy and supported follow-up actions.

## Layout

- Status badge: Active, Expired, Cancelled, Pending verification, or Verification unavailable.
- EWB number, generated time, validity/expiry, source invoice, seller and receiver.
- Item and value summary; transport/vehicle/distance details.
- **View PDF**, **Download**, **Print**, and **Share** actions where permitted.
- Last verified time/source and status refresh action.
- Supported lifecycle actions (e.g. update vehicle, extend validity, cancel) only if the provider API and law permit them.

## Behavior

- Generated document/PDF is retrieved via authenticated backend access or provider-returned document flow.
- Download to device uses native file handling and the OS share/print sheet; show success/failure without leaking a public file URL.
- Before cancel/void or other externally consequential action, show a confirmation with a plain-language consequence.
- Refresh checks provider state and records `lastVerifiedAt` and result. A local cached status is labeled with its timestamp.
- Preserve historic details even when expired/cancelled; never edit a generated bill's underlying invoice in place.

## Data and security

- EWB record stores provider identifier, EWB number, linked invoice ID, state, validity, `generatedAt`, `lastVerifiedAt`, and minimal redacted request/response metadata.
- PDFs and provider documents are private Storage objects with business-member access checks.
- Audit externally consequential changes with actor, time, action, result, and provider reference.
